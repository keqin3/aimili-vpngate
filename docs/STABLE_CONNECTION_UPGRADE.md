# V2.1.7 稳定连接与同国家接替

## 为什么之前会反复自动换 IP

1. 公共 HTTP/SOCKS 代理健康检查也要求 Linux 的 tun0 网卡，未运行 OpenVPN 时会被误报为失效。
2. 自动切换入口没有“已有健康连接就保留”的中央保护；恢复只按全局延迟排序，未限制原国家。
3. 公共代理目标预检失败会清掉原上游；OpenVPN 切换前也过早清掉公共上游。
4. Docker 镜像未安装健康检查需要的 curl。

本次分别修复，而不是仅提高失败阈值。

## 面板操作

升级后，节点列表上方新增“连接切换策略”：

- **健康时：稳定保持，仅手动换 IP**（默认）：节点正常就保持，不会因抓取到更快节点、后台整理、补齐而换出口。
- **失效后自动同国家接替**（默认勾选）：连续 3 次出口检查失败或 OpenVPN 进程已退出时，尝试同国家备用。瞬时失败不切换；本机网关服务没启动不通过轮换远端 IP 来掩盖。
- 想**严格全手动**：选择稳定保持，并取消勾选“失效后自动同国家接替”。
- 想**定时换 IP**：选择“按连接时长轮换”，设置分钟数，点保存。范围 5 分钟至 7 天，默认 60 分钟。每次实际连接成功重新计时；开启/修改时长从保存时重新计时，不会保存后马上跳 IP。
- 如果启用了旧的**固定 IP 路由模式**，它优先于轮换策略：不会轮换其他 IP，故障只重连原节点。想要同国家接替/定时轮换，用自动路由或固定地区路由配合新策略。
- 手动断开仍会停用连接，不会在后台偷偷重连。

保存切换策略不修改账号、安全路径、端口或其他路由条件；策略持久化在原 ui_auth.json，升级后缺少新字段时自动补为稳定模式。

## 同国家与相近地区

- 同国家是候选选择边界，不允许找不到同国家备用就跳到其他国家。
- 优先同城市，其次同地区，再按 GeoIP 经纬度距离和实测延迟排序；元数据不足时只能做到同国家，不把数字相近的 IP 当作地理相近。
- 公共代理与 OpenVPN 备用都可参与；仍遵守已有固定国家、收藏范围、住宅/机房路由过滤。
- 保留最后成功出口的国家/位置锚点，清理连接状态后也不忘记原国家。
- 自动目标核对实际/缓存的真实出口国家；未知或不同则拒绝接替，不把来源声明冒充实际出口验证。
- 候选失效时尝试下一同国家候选，每轮最多 3 个，自动尝试有 60 秒冷却；用户较新的手动操作或取消优先。
- 没有可用同国家备用时保留尚存连接，显示等待补齐，不伪造可用状态。

**边界**：免费节点、单 OpenVPN 隧道和改变公网出口 IP，不能保证零中断或保持原 TCP 会话；切换期间应用可能需要重连。GeoIP 信息也只是位置推断，不保证真实物理距离。应准备多个已实测的同国家备用，接替才更及时。

## Linux 源码升级（root）

```bash
curl -fsSL https://raw.githubusercontent.com/keqin3/aimili-vpngate/main/upgrade.sh -o /tmp/aimili-upgrade.sh
bash /tmp/aimili-upgrade.sh
cat /opt/aimilivpn/VERSION
```

应显示 **2.1.7**，然后浏览器 Ctrl+F5。脚本保留登录配置、节点数据、IP 换批历史；旧 200/50 缓存池功能不变。

Docker 用户须从 keqin3 本仓库源码重新构建（未发布新的远程镜像）：

```bash
git pull --ff-only origin main
docker compose build --pull
docker compose up -d --no-deps aimilivpn
```

保持原 Compose 项目目录/名称和数据卷，勿执行 down -v。
